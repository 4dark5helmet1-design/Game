# Промпт для следующей сессии

Всё ниже — то, что надо знать, чтобы начать без раскачки. Скопируй целиком
в первое сообщение новой сессии.

---

## Кто ты и что за проект

Ты единственный разработчик игры **ЗАБОЙ** — шахтёрский кликер от первого
лица. Проект личный, не связан с остальными репозиториями владельца.
**Рабочий язык — русский.** Отвечай по-русски всегда.

Ветка: `claude/clicker-game-4mnxis`. Пушить только в неё.

## Что нельзя менять (решено давно, не переобсуждается)

- Название ЗАБОЙ, вид от первого лица, телефон в первую очередь плюс комп
  тем же кодом.
- **Проиграть нельзя.** Терять можно только людей из бригады и то, что не
  успел поднять наверх.
- Тон: **странно и тревожно**, без мяса.
- Игрок — тот, кто писал дневники. Финал — **СМЕНА** на 6000 м, цикл.
- Кирка одна, она же мультитул, и апгрейдится только она.
- Пояс: **4 вещи + 3 активных скилла**. Пассивки в ячейки не лезут никогда.
- Esc — меню, Tab — инвентарь, WASD — ходьба, цифры — пояс.
- Настройки переживают перезагрузку.
- Имена вроде R2D2, Додоко, Хелло Китти взяты из чужих вселенных. Пока
  проект личный — оставлены как есть. Перед любой публикацией переименовать.

## Задача сессии: разнести один файл на модули

`docs/demo.html` — почти 5000 строк, вся игра в одном замыкании. Это
последняя большая недоделка, она записана в роадмап дизайн-дока.

**Жёсткое требование:** игра обязана остаться **одним файлом**, который
открывается двойным щелчком и публикуется артефактом. Значит режем
исходник, а не поставку.

Как:

1. `src/` — куски по смыслу: мир и генерация, рендер и шейдер, игрок и
   управление, руда, крафт, интерфейс, звук, тексты.
2. `tools/build.py` собирает их встык обратно в `docs/demo.html`, а
   `tools/release.py` (уже есть) делает из него `docs/zaboy.html`.
3. **Первый заход — тупая склейка по порядку.** Те же строки, те же
   переменные, то же замыкание. Собранный файл должен получиться почти байт
   в байт нынешним — это и есть доказательство, что ничего не сломано.
   Настоящие ES-модули с импортами не делать: всё состояние общее
   (`P`, `SAV`, `CUTS`, `den`, `gl`), и разведение границ — отдельная
   работа на потом.
4. Резать по одному куску за заход, и **каждый заход заканчивать зелёной
   проверкой**.

## Как проверять (обязательно перед каждым коммитом)

```
sh tools/check.sh
```

Делает две вещи: `node --check` на игровом скрипте и playwright-регрессию.
Отдельно регрессия по любому файлу:

```
NODE_PATH=/opt/node22/lib/node_modules node tools/tests/regression.js docs/zaboy.html
```

Playwright лежит в `/opt/node22/lib/node_modules`, без `NODE_PATH` не
найдётся. Браузер запускать с `--use-gl=swiftshader
--enable-unsafe-swiftshader`. **1–4 fps здесь норма**: видеокарты нет,
рендер программный. Не принимай это за тормоза игры.

## Агенты: кого заводить и на чём

Создать в `.claude/agents/`. `tools:` — это белый список: не написал
`Bash` — агент не сможет ничего запустить и будет честно докладывать, что
всё хорошо, ничего не проверив.

| агент | модель | инструменты | зачем |
|---|---|---|---|
| `проверяльщик` | haiku | Read, Bash | гоняет `tools/check.sh`, докладывает «чисто» или список падений |
| `испытатель` | sonnet | Read, Write, Bash | пишет одноразовые playwright-пробы под конкретный вопрос |
| `ревьюер` | opus | Read, Grep, Glob | читает diff, ищет рассогласования: шейдер против JS, порядок инициализации, состояние, переживающее смену, знаки и множители |
| `летописец` | opus | Read | дневники, названия, описания. В бриф обязательно три-четыре готовых листка как образец голоса |

Fable у владельца нет — летописца на opus.

**Правки в `demo.html` агентам не отдавать.** Файл один, правки точечные,
два агента затрут друг друга. Пусть предлагают — применяешь ты.

## Как беречь токены

- Не читай `docs/demo.html` целиком. Ищи `Grep`, читай куском через
  `sed -n 'A,Bp'`.
- Не запускай агента, чтобы «сходить посмотреть» — это дороже, чем
  посмотреть самому. Агент окупается на повторяемой проверке и на тексте.
- Скриншоты дороги. Делай их, только когда вопрос именно про картинку.
- Не пересказывай сделанное дважды: один раз в коммите, один раз в ответе.

## Грабли, на которые я уже наступал

- **Никогда не резать файл по индексам** (`s[s.index(a):s.index(b)]`) —
  так однажды вырезало 500 строк и 60 функций. Только точечная замена
  уникальной строки с проверкой, что вхождение ровно одно.
- **Всегда `sh tools/check.sh` перед коммитом.** Один раз запушил файл с
  повторным объявлением `const` — игра не поднималась вообще.
- Игра завёрнута в IIFE: `page.evaluate` не видит внутренностей. Для
  проверок собирать копию в scratchpad, дописав `window.__z = {...}` перед
  `})();`.
- В артефакте игра крутится во встроенном фрейме: **захвата мыши там нет**,
  работает своя подделка свободного обзора. Локально в обычной вкладке
  захват есть — то есть локальный тест не докажет, что во фрейме работает.
- Playwright под захватом мыши сам крутит камеру своими движениями. Если
  прицел «не находит породу» — сначала проверь, куда камера смотрит.
- Страница при перезагрузке дописывает сохранение поверх. Чтобы подсунуть
  своё, ставить его через `addInitScript`, а не `evaluate` + `reload`.
- Все игровые окна времени считать по `performance.now()`, а не по кадрам:
  на слабом железе кадры растягиваются.

## Где что лежит

- `docs/demo.html` — игра. Артефакт:
  https://claude.ai/code/artifact/eae4f8cd-964c-48f4-9e37-c12dd69fff99
- `docs/zaboy.html` — та же игра одним файлом без страницы вокруг,
  собирается `tools/release.py`.
- `docs/gdd.html` — дизайн-док. Артефакт:
  https://claude.ai/code/artifact/d99aa8fa-31f2-431b-8703-63097110aea7
  Первая секция честно говорит, какая половина документа описывает старый
  замысел, а какая сверена с кодом.
- `docs/spoilers/NE-OTKRYVAY.md` — секреты. **В артефакты не публикуется.**
- `desktop/` — обёртка на Electron для настоящего .exe. Собирать на
  Windows: `npm install && npm run dist`. На Linux упаковка проходит, но
  подпись требует Wine и падает.
- `tools/check.sh`, `tools/tests/regression.js` — проверки.
